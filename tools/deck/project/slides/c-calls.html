Verification · Call lookup and rating

Every call to a customer can be found, heard and rated inside the CRM, but only after the approvals

Approvals first

Nothing opens on its own. Governance requests the call recording on the file with the reason, once verification has a final result. The business head approves. Only then can the calls be looked up, heard or rated; the API refuses before that, whoever asks.

Every call for the number

One button on the file asks our recording server for every call to or from the customer's numbers: when, which way, how long, which extension, with a player. The bot's own calls to the same customer are listed with them. Lookups and listens go to the access log.

Governance rates what it hears

Each call gets a score out of 10 and a note, kept on the file's history and revisable. The recording server's address, credentials and audio never reach the browser: the CRM fetches the audio itself and the link carries no part of the number.

STRIDE · 16

The point for the CEO: a complaint or a quality check no longer means asking IT for a recording and waiting. Once the business head approves the request, governance sees every call to that customer on our recording server, listens inside the CRM and scores each one; the first listen closes the request as received. The table is illustrative. What IT needs: the recording server connected to the CRM, either its recordings folder mounted read-only on the CRM server or its API with a token; the README has both. Nothing about the recording server reaches the browser.
